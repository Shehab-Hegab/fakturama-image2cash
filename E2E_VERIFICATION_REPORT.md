## Live desktop attempt

A live run was attempted against the running Fakturama process on 2026-08-15.
It attached successfully and reached the New Order editor. The desktop session
then rejected Windows keyboard injection with `SendInput() inserted only 0 out
of 2 keyboard events`, after UIA focus returned a COM error. The run stopped
before it could write the date, so it did **not** create or alter an Order or
Invoice.

This is therefore not a completed live E2E verification. The run log and UIA
element dump are retained as diagnostics in `e2e_run_final.log` and
`assets/screenshots/failure_unknown.elements.txt`. A successful acceptance run
requires an interactive Windows desktop session that permits input injection;
then the four required proof screenshots are generated by the flow.

## Safety checks enforced in the implementation

- No coordinate-based mouse actions remain in `src/fakturama_i2c/flow`.
- Every workflow step is fatal on an unresolved UIA control or a mismatch.
- Totals must exactly match 146.53 EUR / 27.84 EUR / 174.37 EUR before
  follow-up invoice creation.
- Payment method is exact-match only; no default or fuzzy payment selection.
- Invoice creation uses only the Order follow-up `Invoice` role.
- Document verification requires exactly one open Order and one matching paid
  Invoice; Delivery, Correction, and Dunning creation are absent.
